# v101 runtime findings and v102 correction

The supplied v101 logs show two complete initialized ragdolls using the correct infected mesh. Warmup took approximately190 and169ms. Captured velocities were zero and about0.215m/s, with recorded sample age17ms in both cases. The upload does not say whether either infected was visibly running. Those values alone are insufficient to establish a capture defect or visible momentum success/failure.

One concrete defect is visible: subtracting the newly activated body's downward velocity generated an upward23.108Ns correction in the second case. That cancels natural settling rather than preserving ground travel. v102 sets the velocity correction's vertical component to zero, retaining gravity and only transferring horizontal travel.

A separate weakness in v101 is prioritizing native controller velocity whenever it is nonzero. Animated AI controller velocity may not represent the visible world displacement; the log lacks both values, so this remains a possible cause of underestimated travel rather than a proven cause. v102 prioritizes the recent world-motion estimate (including an explicitly stationary zero), with native velocity only when no fresh estimate exists. Both values and the selected source are now logged. The minimum displacement sampling interval changes from20 to80ms to reduce zeros/spikes between AI updates; sample recency150ms and invalid speed20m/s rejection remain. This is an average with limited delay, not an exact instantaneous limb/center-of-mass velocity.

The warmup, activation rollback, one-shot impulse and five-second respawn remain. No further forces are applied after handoff. Pelvis world displacement relative to reveal is logged once near100ms and once near300ms, together with root velocity. A root controller alone may not reflect articulated motion, so pelvis tracking gives another observable. Pelvis motion also includes gravity/contact dynamics and does not by itself isolate impulse contribution; stationary/moving comparisons and user observation are needed.

The actual adapted capture-selection, sampling and helper methods pass C++ logic checks for world-motion priority over smaller native readings, recent measured zero overriding native noise, stale/invalid fallback, gravity-preserving correction, no repeated force, pose warmup, failed warmup/activation rollback, cleanup and teleport rejection. This verifies program logic, not native engine impulse propagation. The PBO/ZIP packager validates source bytes, offsets, prefix/checksum and archive integrity. The mission file remains byte-identical to v101. Native v102 compilation/rendering need the local game.
